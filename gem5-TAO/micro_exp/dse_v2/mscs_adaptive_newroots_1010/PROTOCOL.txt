Three methods, each run afresh
  scalar_excess, fixed hybrid (scalar1 + MSCS best distinct1), adaptive.
  Four roots x three methods x six rounds x two candidates = at most144 new
  candidate forward verifications, 48 per method. Root forward/JVP costs separate.
  No pure-MSCS fourth arm, exhaustive label audit, new gem5 or retraining.
  All methods get the same generator and area cap; no performance-label cache
  is shared across methods. Each adaptive trajectory starts with zero losses.
  Each candidate pair is frozen before its CPI/area is evaluated.
